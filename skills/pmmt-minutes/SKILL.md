# PMMT 議事録スキル

PMMT の録音の文字起こしや Notion のメモから、**進捗確認アプリの「議事録・過去の回の取り込み」画面にそのまま貼り付けられる Markdown** を作る。

## 入力として受け取るもの（あるものだけで OK）

- 録音の文字起こし（話者ラベルがなくてもよい）
- Notion の PMMT ページを Markdown で書き出したもの（過去の回の取り込み時）
- アプリの記録を書き出した Markdown（前回までの TODO の確認用）
- PMMT の日付（わからなければユーザーに聞く）

## 出力形式（厳守）

アプリはこの見出しと書き方で 1 件ずつに分けるので、**見出しの文言・順番・箇条書きの形を変えない**。

```markdown
# PMMT YYYY-MM-DD 議事録

## 決まったこと
- [ユニット名] 決まった内容を一文で: 補足（理由・条件・期限など。なければ「:」以降を省く）

## TODO
- [ユニット名] 誰が何をするか（期限: 次回の PMMT まで など）

## 先送りした議題
- [ユニット名] 議題: 先送りした理由・次にやること

## 要約
3〜6 行の文章。平メンバーや新入生が読んでもわかるように、専門用語には一言説明をつける。
```

## ユニット名

`[ ]` の中は、次のどれかを **表記そのまま** 書く（アプリが名前で照合する）。どのユニットか判断できない時は `[ ]` ごと省く。

- プロジェクト: `FinanSu` / `SeeFT` / `Group-Manager` / `HomePage`
- チーム: `Seeds` / `Design Team` / `Infra Team` / `DS Team`
- `局長`（実行委員・他局に関わること） / `副局長`（情報局の運営に関わること）

> ユニット名が変わったら、このリストを更新すること（アプリの管理画面の「報告ユニット」と一致させる）。

## 書き方のルール

1. **「決まったこと」には、その場で合意されたことだけ** を書く。「〜かも」「検討する」で終わった話は「先送りした議題」か TODO にする。
2. TODO は **主語（どのユニットが）と動詞** がわかる形で書く。期限が話に出ていれば添える。
3. 1 行 = 1 件。1 つの箇条書きに複数の決定を詰め込まない。
4. 箇条書きの 2 行目以降に補足を書く場合は、スペース 2 つでインデントする（アプリが直前の項目の補足として読む）。
5. 進捗報告の中身（今週やったこと）は議事録に書かない。アプリの事前記入に残っているため。
6. 文字起こしで聞き取れない・判断に迷う箇所は推測で埋めず、最後に `<!-- 要確認: ... -->` のコメントで残す（アプリはコメント行を無視する）。
7. 個人の評価やプライベートな話題は書かない。

## 過去の回（Notion ページ）を変換する時

- Notion の「決まったこと」「議事録」欄から、上の 3 区分に振り分ける。
- 「このMTで確認すること」で結論が書かれていないものは「先送りした議題」に入れる。
- 文字起こしがある回は、Notion のメモと突き合わせて抜けている決定を補う。
- 1 回分ずつ出力する（アプリには 1 回ずつ貼り付ける）。

## 仕上げ

出力の最後に、次のチェック結果を一言で添える（取り込み前の確認用。アプリには貼らない部分として `---` の下に書く）。

- 決まったこと / TODO / 先送り の件数
- ユニットを判断できなかった項目の数
- 要確認コメントの数
